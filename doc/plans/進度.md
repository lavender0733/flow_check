## 前端頁籤註冊(階段 F,7.3.1)

**加一個頁籤從「改 5 個地方」變成「丟兩個新檔」。**

```
web/partials/xxx.html    <div class="panel hidden" id="panel-xxx">…</div>
web/js/xxx.js            結尾呼叫 registerTab({id, label, order, …})
```

重整瀏覽器即生效,不必重啟(`render_index` 每次請求重掃目錄)。

| 改了什麼 | 怎麼改 |
|---|---|
| `web/js/util.js` | 新增 `registerTab()` 與 `TABS` 註冊表、`isTabOpen()` |
| 四個頁籤模組 | 各在檔尾註冊自己(`order` 10/20/30/40,中間留空檔供插入) |
| `web/js/main.js` | 不再認得任何頁籤,只依 `order` 生按鈕列、跑三個 hook |
| `core/routes.py` `render_index` | 改掃 `web/partials/` 注入面板與 `<script>` 標籤 |
| `web/index.html` | 剩 `<div class="tabs" id="tabs">` 與兩個標記 |

### 為什麼掃 partials 而不是掃 `web/js/*.js`

設計文件第 5.2 節原本寫的是掃 `web/js/*.js`。**實作時改掉了**,因為那個做法
會把兩種檔案載進網頁:

- 放在 `web/js/` 的備份檔(`monitor_舊版.js`)
- **Google Drive 同步衝突自己長出來的 `monitor (1).js`**

兩者都與正版定義同名函式,而且**字母序排在正版後面**(`.` 的 ASCII 是 46、
`_` 是 95、空白是 32 —— `monitor.js` 先載入,後載入的蓋掉它)。症狀是
「明明改了程式卻沒生效」,不報錯、極難查。

改成「每個頁籤由一個面板 + 一支同名 js 成對組成,沒有配對面板的 js 一律不載入」
之後,**備份檔放在 `web/js/` 裡是安全的**。已實測驗證這兩種檔都不會被載入。

> 順帶一提:導入 git 之後其實不該再放 `_舊版.js` 這種備份(用
> `git show HEAD~3:web/js/monitor.js` 就能看任一版)。但 Drive 的衝突副本
> 不是人放的、擋不住,所以這條規則仍有價值。

### 三個 hook 的語意

| hook | 何時跑 |
|---|---|
| `onInit()` | 頁面啟動時跑一次,**不論這一頁是否顯示** |
| `onFirstShow()` | 第一次切到這一頁時 |
| `onShow()` | 每次切到這一頁時(含第一次,在 `onFirstShow` 之後) |

全域旗標 `calcLoaded` 因此移除 —— 「只在第一次開啟時抓」由 `onFirstShow`
的語意直接表達,不必自己記。

## 還留著的三個坑(日後改到那裡要當心)

### 1. `quota.API_QUOTA_BASELINE_PATH` 完全不經過 `BASE`

`_load_quota_baseline()` 直接讀這個模組層常數,而 `api_quota_status()` 會呼叫它。
`data/config/api_quota_baseline.json` 是**含 `userCode` 的機密檔**。

日後若要在暫存目錄裡驗 `api_quota_status()` 本身,只換掉 `BASE` 仍會讀到
真實機密檔,務必一併換掉 `quota.API_QUOTA_BASELINE_PATH`。

### 2. `stop_monitor.bat` 用「命令列含 `traffic_monitor.py`」比對砍程序

**那個檔名不能改**,改了就砍不掉。

### 3. `API_ERR` 的錯誤分類把四種原因混成一種

拿一組亂打的驗證碼去跑檢索,畫面顯示:

```
TIPO 回覆額度已滿/維護(API_ERR: message=userCode not exist)
```

**兩句話自相矛盾** —— TIPO 明說「驗證碼不存在」,外層卻套上「額度已滿/維護」。
照那個提示會去等額度恢復,但等多久都不會好。

成因在 [gpss_api_query.py:791](../../program/gpss/gpss_api_query.py):
`if status.startswith("API_ERR")` 把超額、維護、驗證碼錯、參數錯**全歸成同一類**,
而 `interpret_batch()`(同檔 439 行)只是把 TIPO 的訊息原樣串進 status 字串。

修法:在 `interpret_batch()` 判斷 TIPO 訊息內容,`userCode` / `不存在` / `驗證`
類的回 `AUTH_OR_ERROR`,超額類才保留「額度已滿/維護」。**與重構無關,獨立一條做。**

## 為什麼是現在這個做法(決策紀錄)

| 決定 | 理由 |
|---|---|
| 走方案 B,不走 C | 妳還不確定要加什麼功能,所以投資在「不論加什麼都會經過的兩個窄口」:新端點、新頁籤。C 的 ES module 改寫要動每個 partial 的 `onclick`,在前端沒測試的情況下是純風險 |
| **階段 F 一度放棄** | 動 `main.js` / `index.html` 沒有任何自動化擋得住,而「新增頁籤」不是常做的事。後端的效益已經拿到,停在這裡是划算的停損 |
| **後來又做了階段 F** | 使用者說「未來要加的新功能都會是新頁籤的形式」,推翻了上面那個前提。風險則用 Playwright 實際點頁面解掉(專案本來就有這個相依) —— 當初的顧慮是「沒有自動化擋得住」,不是「這件事做不得」 |
| 掃 `partials/` 而非 `web/js/*.js` | 設計文件原本寫掃 js。實作時改掉:Drive 同步衝突會自己長出 `monitor (1).js`,它與正版同名函式又排在後面,會靜默蓋掉正版 |
| git repo 放 Drive 裡 | 只有 42 檔 / 551 KB,同步負擔可忽略;損毀情境需雙機同時操作 git 才會發生。換來的是版本歷史隨 Drive 自動備份 |
| 測試寫在重構**之前** | 針對現行行為寫,才是安全網;寫在之後只是替新程式碼背書 |
| `data/` 檔名與格式不動 | 那 111 筆執行紀錄與 11 筆快照是真實累積的歷史,改格式就得寫遷移。方案 B 本來就不需要動 |
| 保留 `<檔名>_<機器代號>` 分檔 | 7.2.1 才剛修對合併邏輯,拆掉只是白冒險 |
| `mask_code` 統一採「有 strip」 | 另外兩份是餵給網頁的額度卡與月進度卡,顯示必須對齊,以現行網頁為準 |
