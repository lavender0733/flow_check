## Task 17 完成了什麼

`traffic_monitor.py` **1,536 → 167 行**。裡面只剩 docstring、bootstrap、
`VERSION`、`_ensure_machines_file()`、`_startup_banner()`、`main()` ——
就是「載設定 → 造 Monitor/JobRunner → 起兩個背景迴圈 → 開伺服器」。

16 個端點搬進 `core/routes.py`，各自成一個函式，最下方一張 `build_routes()` 註冊表。

**四個實質改善（不只是搬家）：**

| | 舊 | 新 |
|---|---|---|
| 路徑比對 | `startswith` 長鏈，順序錯就靜默吃掉 | `(method, path)` 精確比對，順序無關 |
| 亂打的路徑 | `/api/statusXYZ` 被 `/api/status` 收下，回 200 | 回 404 |
| query 參數 | 手刻 `re.search(r"month=...")` | 底座統一解析 |
| 錯誤處理 | 每個端點各包一層 `try/except` | 底座統一收斂 + 記進 `record_error` |

**兩個端點刻意保留自家的 `try/except`**：`/api/monthly` 與 `/api/monthly/trend`
失敗時要回 **200 加空陣列**（前端直接拿 `points` / `months` 渲染），
給它 500 會讓整張達標分析圖連同月份下拉一起消失。這在測試裡鎖住了。

### 過程中發現並修掉的兩件事

**1. `?month=xyz` 的行為會悄悄改變。** 舊版用 regex 從 query string 撈
`(\d{4}-\d{2})`，撈不到就是 `None`（退回當月）。底座改為原樣交出 query 值，
所以 `?month=xyz` 會被直接送進 `trend()`、回一個空月份。已在端點補上格式檢查，
行為與舊版一致（測試 `test_trend_rejects_malformed_month` 鎖住）。

**2. 靜態檔白名單回 403，害 `/api/statusXYZ` 偏離舊版。** 計畫 Step 11 要求
那個路徑回 404，實測是 403 —— 因為掛上靜態目錄後，**所有沒對到路由的請求都會
落到靜態處理**，而它對「副檔名不在白名單」一律回 403。這是 Task 16 留下的缺口、
在 Task 17 才踩到。已改成 404，順帶更安全：403 等於確認「那裡有東西、只是不給」，
404 連存在與否都不透露。

## 執行方式（沿用，實測有效）

一個 Task 派一個 agent，做完我先審過再往下。彼此獨立的 Task 可並行
（Task 4-7 四個一起跑、Task 9-10 兩個一起跑）。

**給 agent 的指示要包含這幾點**：
- commit 用 `git commit -m`，不要用 heredoc（這個 shell 的巢狀 heredoc 有問題）
- 只 `git add` 自己那個檔，不要 `git add -A`（並行時會夾帶別人的檔）
- 遇到 `.git/index.lock` 就等幾秒重試，不要刪 lock 檔
- **行尾**：`program/` 底下**只有 `traffic_monitor.py` 與 `monthly_progress.py`
  是 CRLF**，其餘都是 LF。用 Edit 工具，或 Python 的 `newline=''`
- 測試指令加 `PYTHONDONTWRITEBYTECODE=1` 前綴，避免產生 `.pyc`
- **測試若失敗，不准改測試去遷就** —— 先判斷是預期寫錯還是程式有 bug，停下來回報
- 常駐伺服器（`start_monitor.bat` / `年度統計.bat`）agent 跑不了，明講留給使用者；
  但 `python program/core/monthly_progress.py` 可以跑（那是 `月進度.bat` 的路徑，
  會印報告後結束），是唯一能完整驗 bootstrap 的進入點

### 關於第 3 點

把 `trend()` 改回 v7.2.0 的 `_load_history()`，**整個 `TestHistoryMerge` 六項全倒**。
因為隔離後 `_load_history()` 讀到空檔，所有依賴快照的斷言都失效。

**這正是那個 bug 的真實樣貌**：使用者換一台電腦看，達標分析圖就整個空掉。

### 關於第 7 點（最危險的一個）

`gpss_api_query.py` 與 `gpss_web_query.py` 各有一段：

```python
try:
    import output_store
except Exception:
    output_store = None
```

套件化後 `program/gpss` 不再在 `sys.path` 上，這兩行會失效 —— **而且不會報錯**。
被 `except` 吞掉、`output_store` 靜靜變成 `None`，檢索照跑但 Excel 彙整不做了，
統計頁空白卻查不出原因。執行 Task 11 的 agent 自己發現並補上了。

計畫已新增 Step 4b 說明這件事，並附一條驗證指令：五個 try/except 匯入
（兩支 gpss 的 `output_store`、`storage` 的 `output_store` 與 `_gpss_module()`、
`traffic_monitor` 的 `monthly_progress`）**每一個都必須印出 `<module ...>`，
任何一行是 `None` 就是漏改了**。

### 關於第 9 點

`yearly_stats/web/app.js` 的 `renderPie` 畫的是**「累積佔年度目標的比例」**，
不是三個系統互相的佔比：三段依序接續（620 約 5% + 630 約 39% + 680 約 39% ≒ 83%），
剩約 17% 是灰色缺口。三段顏色相鄰又同色系，**視覺上就是一個連續的彩色弧**。
個別系統的數字要看**圖例那三行**。

## 成敗判準：Task 22

**Task 22 是整個計畫的驗收關卡。** 它只丟兩個新檔（`web/js/zdemo.js`、
`web/partials/zdemo.html`）然後跑 `git status --short`：

- 只出現兩行 `??` → **成功**，「新增頁籤 = 丟兩個新檔」達成
- 出現任何 `M`（已修改現有檔案）→ **失敗**，退回重做 Task 20 / 21

驗完就刪掉那兩個檔，不 commit。
