## Task 17 完成了什麼（已驗收）

`traffic_monitor.py` **1,536 → 167 行**。裡面只剩 docstring、bootstrap、
`VERSION`、`_ensure_machines_file()`、`_startup_banner()`、`main()` ——

**四個實質改善（不只是搬家）：**

| | 舊 | 新 |
|---|---|---|
| 路徑比對 | `startswith` 長鏈，順序錯就靜默吃掉 | `(method, path)` 精確比對，順序無關 |
| 亂打的路徑 | `/api/statusXYZ` 被 `/api/status` 收下，回 200 | 回 404 |
| query 參數 | 手刻 `re.search(r"month=...")` | 底座統一解析 |
| 錯誤處理 | 每個端點各包一層 `try/except` | 底座統一收斂 + 記進 `record_error` |

**兩個端點刻意保留自家的 `try/except`**：`/api/monthly` 與 `/api/monthly/trend`
失敗時要回 **200 加空陣列**（前端直接拿 `points` / `months` 渲染），
給它 500 會讓整張達標分析圖連同月份下拉一起消失。這在測試裡鎖住了。

### 過程中發現並修掉的兩件事

**1. `?month=xyz` 的行為會悄悄改變。** 舊版用 regex 從 query string 撈
`(\d{4}-\d{2})`，撈不到就是 `None`（退回當月）。底座改為原樣交出 query 值，
所以 `?month=xyz` 會被直接送進 `trend()`、回一個空月份。已在端點補上格式檢查，
行為與舊版一致（測試 `test_trend_rejects_malformed_month` 鎖住）。

**2. 靜態檔白名單回 403，害 `/api/statusXYZ` 偏離舊版。** 計畫 Step 11 要求
那個路徑回 404，實測是 403 —— 因為掛上靜態目錄後，**所有沒對到路由的請求都會
落到靜態處理**，而它對「副檔名不在白名單」一律回 403。這是 Task 16 留下的缺口、
在 Task 17 才踩到。已改成 404，順帶更安全：403 等於確認「那裡有東西、只是不給」，
404 連存在與否都不透露。

- 五個 try/except 匯入全部印出 `<module ...>`，沒有一個是 `None`

### 關於第 7 點（最危險的一個）

## 順手發現、但還沒修的一個 bug

**`API_ERR` 的錯誤分類把四種原因混成一種。** 使用者在 Task 17 驗收時
拿一組亂打的驗證碼去跑檢索，畫面顯示：

```
TIPO 回覆額度已滿/維護(API_ERR: message=userCode not exist)
```

**兩句話自相矛盾** —— TIPO 明說「驗證碼不存在」，外層卻套上「額度已滿/維護」。
照那個提示會去等額度恢復，但等多久都不會好。

成因在 [gpss_api_query.py:791](../../program/gpss/gpss_api_query.py)：
`if status.startswith("API_ERR")` 把超額、維護、驗證碼錯、參數錯**全歸成同一類**，
而 `interpret_batch()`（同檔 439 行）只是把 TIPO 的訊息原樣串進 status 字串。

**與重構無關**（那個檔最後一次變動是階段 B 的 `24f188c`，Task 17、18 都沒碰）。

修法：在 `interpret_batch()` 判斷 TIPO 訊息內容，`userCode` / `不存在` / `驗證`
類的回 `AUTH_OR_ERROR`（那條路徑的訊息是「收到無法靠換台解決的錯誤」，
比較接近事實），超額類才保留「額度已滿/維護」。**獨立一條做，別混進重構線。**

## 一個看起來像 bug、其實不是的現象

**爬取統計的「本月 API 分組」會出現已經刪掉的驗證碼。** 使用者刪了
`api_keys.json` 裡那組亂打的碼，但爬取統計仍列著它（`count: 1`）。

**那張卡的來源不是本機驗證碼池**，是 `monthly_progress.api_breakdown()` 讀
`data/exports/API.xls` —— **TIPO 後台的匯出檔**。用那組碼打過一次 TIPO，
TIPO 那邊就留了一筆紀錄，匯出檔自然有它。

| 三張卡 | 來源 | 刪 `api_keys.json` 有用嗎 |
|---|---|---|
| 本月 API 分組 | `data/exports/API.xls`（TIPO 匯出）| ❌ 沒用 |
| 額度卡 | 本機 `summary_*.csv` 的 OK 列 | — |
| 時段案件數 | 同上 | — |

下次重新下載匯出檔、那筆落在區間外就會消失。**不要手動編輯 `API.xls`** ——
它是原始紀錄，改了月進度與達標分析全部跟著失真，為一列 `count=1` 不值得。
