## 執行方式（沿用）

一個 Task 派一個 agent，做完我先審過再往下。彼此獨立的 Task 可並行
（Task 4-7 就是四個一起跑的）。

**給 agent 的指示要包含這幾點**（實測有效）：
- commit 用 `git commit -m`，不要用 heredoc（這個 shell 的巢狀 heredoc 有問題）
- 只 `git add` 自己那個檔，不要 `git add -A`（並行時會夾帶別人的檔）
- 遇到 `.git/index.lock` 就等幾秒重試，不要刪 lock 檔
- 編輯 CRLF 檔案（`program/` 底下都是）要用 Edit 工具或 `newline=''`，
  否則整檔換行符會被轉換
- 測試指令加 `PYTHONDONTWRITEBYTECODE=1` 前綴，避免產生 `.pyc`
- **測試若失敗，不准改測試去遷就** —— 先判斷是預期寫錯還是程式有 bug，停下來回報

## 執行中發現並修掉的計畫缺陷（5 個）

寫計畫時看不出來、實際跑才會爆的那種。都已修正並 commit。

| # | 問題 | 影響 |
|---|---|---|
| 1 | `測試.bat` 漏抄 `chcp 65001` 與 `PYTHONIOENCODING` | Task 2 起測試訊息含中文，在 Big5 主控台會 `UnicodeEncodeError` |
| 2 | `TestHistoryMerge` 只 patch `MACHINE_DATA_DIR` | `_load_history()` 讀的是 `HISTORY_PATH`，測試會讀到真實快照檔 |
| 3 | 改壞驗證預期寫「三項失敗」 | 實測是六項全倒（**更有說服力**，見下） |
| 4 | 測試檔與計畫都寫「Task 10 統一後會更新」 | 真正替換呼叫點的是 Task 12，會讓執行者找錯地方 |
| 5 | Global Constraints 沒寫測試隔離的陷阱 | 同型態的坑踩了兩次 |

### 關於第 3 點

把 `trend()` 改回 v7.2.0 的 `_load_history()`，**整個 `TestHistoryMerge` 六項全倒**，
不是計畫預期的三項。因為隔離後 `_load_history()` 讀到空檔，所有依賴快照的斷言都失效。

**這正是那個 bug 的真實樣貌**：使用者換一台電腦看，達標分析圖就整個空掉。
