# 架構優化設計 — 讓 flow_check 好加新功能

- 日期：2026-09-14
- 目標版本：**v7.3.0**
- 起始版本：v7.2.1
- 方案：**B（地基整理 ＋ 兩個可擴充點）**

---

## 1. 背景與目標

### 為什麼做

專案目前 Python 5,568 行、前端 2,646 行，沒有版本控制、沒有任何測試。使用者尚未決定
下一個新功能是什麼，因此本次優化的目標**不是**為某個特定功能鋪路，而是：

> **降低「任何一次改動」的成本。**

### 觀察到的七個摩擦點

| # | 問題 | 現況 |
|---|---|---|
| 1 | `traffic_monitor.py` 一檔四責 | 1,536 行：`Monitor` 450、`JobRunner` 314、`Handler` 300、雜項 |
| 2 | 路由是 `startswith` 長鏈且有順序陷阱 | `/api/monthly/trend` 必須排在 `/api/monthly` 之前，否則靜默被吃掉 |
| 3 | 工具函式重複 3–6 份 | `machine_id()` ×4、檔案簽章 ×3、`mask_code` ×3、原子寫入 ×6、容錯讀 JSON ×18 |
| 4 | 兩支 HTTP 伺服器各抄一套管線 | `send_json`、靜態檔、穿越防護、快取標頭、靜音 log 全部重複 |
| 5 | 前端 140 個全域函式共用一個作用域 | 加一個頁籤要改 5 個地方；跨檔相依隱式（`analytics.js` 讀 `progress.js` 的 `monthlyData`） |
| 6 | 沒有測試、不是 git repo | 每次改動只能重啟＋手點驗證，改壞了沒有回退點 |
| 7 | 設定散在 9 個檔 | 無統一結構驗證（**本次不處理**，屬 C 案） |

本設計處理 1–6。第 7 項與前端 ES module 化、`monitor.js` 拆解同屬 C 案，刻意排除。

### 成功判準

完成後應同時滿足：

1. **新增一個 HTTP 端點** = 在 `core/routes.py` 寫一個函式 + 加一行註冊。
2. **新增一個網頁頁籤** = 丟兩個新檔（`web/js/xxx.js` + `web/partials/xxx.html`），現有檔案零改動。
3. **新增一個獨立小工具**（如年度統計那種）= 寫一張路由表，不必重抄伺服器管線。
4. `python -m unittest discover tests` 全綠。
5. 所有既有功能行為不變（端點路徑與回應形狀、資料檔格式、四個 .bat 的用法全部照舊）。

## 2. 不動的邊界

以下在整個重構過程中保持不變，作為「沒改壞」的驗證基準。

### 2.1 進入點檔名

| 檔案 | 誰在叫它 |
|---|---|
| `program/core/traffic_monitor.py` | `start_monitor.bat:111`；**`stop_monitor.bat:15` 用「命令列含 `traffic_monitor.py`」比對來砍程序** |
| `program/core/monthly_progress.py` | `月進度.bat`（需保留 `main()`） |
| `program/yearly_stats/yearly_server.py` | `年度統計.bat` |
| `program/gpss/gpss_api_query.py`、`gpss_web_query.py` | `JobRunner` 以 subprocess 啟動 |

`stop_monitor.bat` 的比對方式使 `traffic_monitor.py` 這個檔名成為硬性約束。

### 2.2 對外介面

- **所有 HTTP 端點的路徑與回應 JSON 形狀不變** → 前端在後端重構期間（步驟 2–6）一行都不用改。
- **`config.json` 與 `data/config/*.json` 的欄位不變。**

### 2.3 資料檔

`data/` 底下所有檔名與格式不變。理由不是多機同步（目前只有 PC17T033 在跑），而是
**那些檔案裝著真實累積的歷史**：

- `run_log_DESKTOP-V33GG01.jsonl` 102 筆 + `run_log_PC17T033.jsonl` 9 筆
- `monthly_progress_history_*.json` 合計 11 筆快照

爬取統計與達標分析目前會合併兩台計算，改格式就得寫遷移。本方案不需要動任何資料格式。

`<檔名>_<機器代號>` 的分檔命名與「讀取時合併所有機器」的邏輯一併保留 —— 該邏輯在 7.2.1
才剛修正，拆除只是徒增風險。

> 若日後確定 DESKTOP-V33GG01 不再使用、歷史數字也不保留，那是獨立的資料清理工作，
> 不併入本次重構。

### 2.4 相依與工具

不新增任何第三方套件（維持 `psutil` / `openpyxl` / `xlrd` / `playwright`），不引入打包工具。
前端維持傳統 `<script>`、全域作用域、HTML 內 `onclick`。

### 3.1 匯入機制

`common/`、`core/`、`gpss/`、`yearly_stats/` 各放一個空的 `__init__.py` 成為套件。
每個進入點開頭加一行把 `program/` 放進 `sys.path`：

```python
import sys, pathlib
sys.path.insert(0, str(pathlib.Path(__file__).resolve().parents[1]))   # → program/
```

之後一律 `from common.jsonio import ...`、`from core.paths import ...`。

這麼做的收益：消掉 `storage.py:20` 現有的「插入 `program/gpss` 到 sys.path」隱式耦合，
把散落各處的路徑魔法收斂成**每個進入點一行**。

`sys.dont_write_bytecode = True` 必須維持在所有 import 之前（Google Drive 同步夾不能留 `.pyc`）。

## 4. HTTP 底座與路由表

### 4.1 `common/webapp.py`

收下兩支伺服器重複的部分：

- `send_json(obj, code=200)`
- 靜態檔服務 + 路徑穿越防護（解析後確認仍在允許目錄內）
- `Cache-Control: no-store, must-revalidate`
- `<!--#include partials/xxx.html-->` 渲染（擴充為目錄掃描，見第 5 節）
- `<!--#version-->` 置換
- 靜音 `log_message`
- 吞掉瀏覽器中途斷線的 `ConnectionAbortedError` / `ConnectionResetError` / `BrokenPipeError`
- **統一例外攔截**：端點函式拋出的例外由底座收斂成 `{"ok": false, "message": ...}` 並記入
  `record_error`，取代目前各端點各包一層 `try/except`（約 8 份）

對外介面：

```python
def serve(port, routes, static_dir=None, index_renderer=None,
          on_error=None, banner=None):
    """建立 ThreadingHTTPServer 並 serve_forever。
    routes: {(method, path): handler}，handler 收一個 Request、回傳可 JSON 序列化的物件。
    """
```

`Request` 物件提供：`method`、`path`（已去除 query）、`query`（已解析成 dict）、`body`
（POST 的 JSON，解析失敗回 `{}`）。

### 4.2 `core/routes.py`

## 5. 前端頁籤註冊

### 5.1 現況

加一個頁籤要改 5 個地方：

1. `index.html` 的頁籤按鈕 `<button class="tab" onclick="showTab('xxx')">`
2. `index.html` 的 `<!--#include partials/xxx.html-->`
3. `index.html` 的 `<script src="js/xxx.js">`
4. `main.js:6` `showTab` 的硬編陣列 `["monitor","control","analysis","calc"]`
5. `main.js:10-13` 的 per-tab hook（`if (name === "analysis") …`）

### 5.2 伺服器端：自動探索

`common/webapp.py` 的 include 渲染改成掃目錄產生：

- `web/partials/*.html` → 全部注入（面板同時只顯示一個，DOM 順序無關，字母序即可）
- `web/js/*.js` → 自動產生 `<script>` 標籤

載入順序只有兩條硬性規則：

- **`util.js` 最先**（它要先定義 `registerTab`）
- **`main.js` 最後**（它是啟動者）
- 其餘照字母序

**此規則的安全性已驗證**：中間四個檔（`monitor` / `control` / `analytics` / `progress`）
的跨檔引用全部發生在函式內（執行期，此時全部已載入）。`progress.js:8` 雖在頂層宣告
`let monthlyData`，但 `analytics.js` 只在函式內引用它。只有 `main.js` 在頂層執行啟動碼。

`index.html` 對應改為：

```html
<div class="tabs" id="tabs"></div>      <!-- 由 main.js 依註冊表生成 -->
<!--#include-partials-->                 <!-- 由底座掃目錄注入全部 partials -->
<!--#include-scripts-->                  <!-- 由底座掃目錄產生 script 標籤 -->
```

### 5.3 前端：自我註冊

`registerTab` 與註冊表放在 `util.js`（它被規則固定在最先載入）。

```js
// web/js/progress.js 結尾
registerTab({
  id: "calc",                 // 對應 panel-calc / tab-calc
  label: "檢索進度",
  order: 40,
  onInit()      {},                      // 頁面啟動時跑一次（不論是否顯示）
  onFirstShow() { refreshMonthly(); },   // 第一次切到本頁
  onShow()      {},                      // 每次切到本頁
});
```

四個頁籤的 `order`：monitor 10、control 20、analysis 30、calc 40。

`main.js` 變成通用的：依 `order` 生出頁籤列、處理切換、在對的時機呼叫三個 hook，
以及 app 層級的輪詢（`tickStatus` / `tickJob` / `updateJobElapsed`）。

### 5.4 順帶清理

| 清掉什麼 | 怎麼取代 |
|---|---|
| 全域變數 `calcLoaded`（`progress.js:9`） | 「只在第一次開啟時抓」由 `onFirstShow` 語意直接表達 |
| `main.js` 開頭 7 行 `restoreDetect()` / `restoreNotify()` / `restoreSurge()` / `restoreExcludeLan()` / `restoreSpeedFloor()` / `restoreCalcLogCollapse()` / `restoreMonitorTab()` | 搬進 `monitor.js` 自己的 `onInit`（本來就全是流量監控頁的事） |
| `analytics.js:189` 與 `control.js:304` 兩處硬編的 `document.getElementById("panel-analysis").classList.contains("hidden")` | 新增 `isTabOpen(id)` |

### 5.5 刻意不做

- **不改 `panel-analysis` / `panel-calc` 這些與檔名對不上的 id。**
  （`analytics.js` → `panel-analysis`、`progress.js` → `panel-calc`）
  註冊表用 `id` 明寫，名稱對不上就不痛了；硬改要動 partial、CSS 和一堆選擇器，純風險。
- **不碰那 140 個全域函式、不碰 `onclick`、不拆 `monitor.js` 的 818 行。** 屬 C 案。

### 5.6 結果

**新增一個頁籤 = 丟兩個新檔（`web/js/xxx.js` + `web/partials/xxx.html`），現有檔案零改動。**
