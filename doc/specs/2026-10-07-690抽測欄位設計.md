# 690 抽測欄位(s690 查詢)— 設計

> 2026-10-07 定案。分支 `feat-690`。實作計畫另寫在 `doc/plans/`。

## 要做什麼

KM 上有五欄要人工上 s690(`https://cloud.tipo.gov.tw/s690/ui/`)查了再填,改成程式查、放進現有的 KM 預覽,
照舊由使用者按「寫入 KM」(或「只寫這一列」)寫入。

| KM 頁 / 表 | 欄 | 填什麼 |
|---|---|---|
| `TW書目Biblio及雜項` TWA、TWB | 690查詢筆數 | s690 該日的總筆數 |
| 同上 | SUD抽測案例 | 抽到的案號,`TW` + 公開 / 公告號(例:`TWI933653`、`TW202636009`) |
| 同上 | 備註 | 抽測比對正確 → `成功` |
| `TW影像GCS` 公開影像上傳、公告說明書上傳 | 說明書 | 那期檢索結果的第一筆有說明書 → `v` |
| 同上 | 代表圖 | 同一筆有代表圖 → `v` |

## 做法:直接呼叫 s690 的 API

s690 是單頁網頁,背後是 oRPC:`POST https://cloud.tipo.gov.tw/s690/ui/main/rpc/<路徑>`,
body `{"json": {...}}`,回 `{"json": {...}}`。**不用登入、不開 VPN 也通**(2026-10-07 實測)。
User-Agent 跟 KM 一樣送 `flow-check-xfer690/1`。

沒有公開文件,對方改版就可能壞。壞了只在預覽顯示錯誤,**不會寫錯值進 KM**(查不到的格就不填)。

不採用:Playwright 點網頁(慢、脆、多一個相依);只產生連結給人看(沒有自動化)。

### 用到的呼叫(實測過)

| 路徑 | 輸入 | 用途 |
|---|---|---|
| `patent/search/fetchSearchId` | `query`、`options`、`sortBy`、`sortOrder` | 回 `total`、`searchId` |
| `patent/search/fetchSearchResultsByPieces` | `searchId`、`page`、`pageSize` | 一頁結果 |
| `patent/miscellaneous` | `apn`、`database`(`TWA` / `TWB`) | 該案所有雜項,每筆有 `type`、`volno`、`isuno`、`items` |

`options`(進階檢索「展開設定 → 案件類型」):

```json
{"countryCodes": ["TWA", "TWB"], "onlyDomestic": true, "caseTypeCodes": ["TWA"],
 "caseStatusCodes": [], "patentTypeCodes": [], "rightsChangeTypeCodes": [], "dualApplication": false}
```

`sortBy: "PD"`、`sortOrder: "desc"`。案件類型 `TWA` = 公開、`TWB` = 公告,依表格(系統的 `view`)決定。

結果每筆用得到的欄位:`pnRaw`、`apnRaw`、`database`、`volno`、`isuno`、`caseStatusCode`、
`currentAssignees`、`hasPublishedSpecification` / `hasIssuedSpecification`、
`gazetteFigures`(含 `<representative>` 即有代表圖)。

## 每一欄的規則

### 690查詢筆數

- 檢索式 `PD:[<日期> TO <日期>]`,日期 = 那一列的資料日期(`date_of_vol`,與 Biblio 列同一期)。
- 填 `total`。跟 Biblio 不同時照填,但預覽用波浪底線標(沿用筆數欄現有的「頁面值 vs 計算值」標示方式),tooltip 寫兩個數字。
- 實測:10-01 TWA 2384、TWB 1640,與 Biblio(L1 writes)相同。

### SUD抽測案例、備註

信裡的 `.log` **沒有逐筆案號**,只有各類雜項的筆數(雜項 RAW 那段:
`XML parsing completed (type=sud11, recordCount=90)`)。所以:

1. **從 log 取這期有哪些雜項類型**(`parse_raw` 多抓這種行,存成事件的 `sud_types: {type: count}`)。
   排除目錄類:TWB 的 `sud00_1`(公告目錄)、TWA 的 `pubsud01`(發明公開目錄)—— 每案都有,不算雜項異動。
   排除後沒有任何類型時才用目錄類。
2. **一次查完**:`MS:(類型1 OR 類型2 …) AND MS:<卷> AND MS:<期>`,案件類型同表格,照 PD 新到舊。
   (`OGV`/`OGN` 篩的是案件本身的公報期數,不是雜項刊登的期數,所以不用。
   `MS:sud11-5328` 這種連字號寫法無效,換哪一期結果都一樣。)
3. **取符合的第一筆**:照結果順序逐筆查 `patent/miscellaneous`,第一筆「有一筆雜項是這些類型之一、
   且 `volno`/`isuno` = 這一期」的案件就是抽測案例,停止往下查。
   `MS:<卷> AND MS:<期>` 不保證兩個值在同一筆雜項上,所以一定要核對。
   一頁 40 筆,最多翻 3 頁;都沒有 → 記為「找不到」。
   實測:5328(sud11 OR sud08)第一頁 20 筆中 16 筆符合;2419(pubsud06)20 筆中 14 筆;一次 2–5 秒。
   較舊的期命中較少(24/13 第一頁 0 筆),靠翻頁補。
4. **比對**(依抽到那筆雜項的類型):

   | 類型 | 判定成功 |
   |---|---|
   | `sud11` 讓與 | 書目 `currentAssignees` 含雜項的「受讓人」(比對前去掉全形 / 半形空白) |
   | `sud08` 消滅 | 書目 `caseStatusCode` = `expired` |
   | 其他(含 `pubsud06`) | s690 查得到這筆雜項、且期數 = 這一期 |

5. **填值**:成功 → 案例填 `TW` + `pnRaw`,備註填 `成功`。
   比對不符或找不到 → **兩格都不填**,預覽在那一列亮紅色、寫原因(類型、雜項值、書目值),由使用者決定。
6. 結果存起來,同一期**不重查**;但雜項 L1(`011103` / `011203`)之後又重跑過(最後一次執行時間比查詢時間新),
   就重查一次。案例那格滑過去顯示比對內容。

### TW影像GCS:說明書、代表圖

- **期數跟書目走**:列 = 書目系統(`twa-biblio` / `twb-biblio`)有收到信的期。頁面上沒有的列照現有規則新增(`new_row` 只填期數)。
- 檢索式 `OGV:<卷號> AND OGN:<期數>`(2413 → 卷 24、期 13;5328 → 卷 53、期 28),案件類型同表格。
- 取結果的第一筆(只要 `pageSize: 1`):
  - 說明書:TWA 看 `hasPublishedSpecification`,TWB 看 `hasIssuedSpecification`,為真 → `v`
  - 代表圖:`gazetteFigures` 裡有 `<representative>` → `v`
- 沒有的格不填,預覽標原因。抽到的案號同樣存起來、滑過去看得到。
- 書目重跑過(L1 最後執行時間比查詢時間新)→ 筆數與影像重查。

## 什麼時候查

- 抓完信(自動或「立即更新」)後,在背景執行緒查,不擋抓信。
- 查的對象:期的狀態是 `ok`(整期每步都成功)、而且還沒有成功的查詢結果。
  - 筆數、影像:看書目系統那一期。
  - 抽測:看雜項系統那一期。
- **成功的結果存進快取(`xfer690_<機器>.json` 的 `s690`),不重查**;失敗的下一次抓信再試。
  快取鍵 `<twa|twb>:<期數>`,內容 `{count, image, sud, at, error}`;過了 `retain_days` 跟著事件一起清。
- s690 回 0 筆或查不到案件時先當暫定,24 小時內每次抓信再查;之後才接受。
- 每次只查還缺的;抽測最多 3 頁 × 40 筆(每筆一個雜項查詢),但每期只查一次。

## 程式結構

| 檔案 | 變更 |
|---|---|
| `program/xfer690/s690.py`(新) | `S690Client(post=...)`:`count(case_type, day)`、`image_check(case_type, vol)`、`sud_sample(case_type, vol, types)`。純 urllib,`post` 可注入(測試用假的)。不用隨機,結果可重現 |
| `parser.py` | `parse_raw` 多抓 `sud_types` |
| `status.py` | 期多帶 `sud_types`(該期事件合併) |
| `service.py` | 背景查 s690、存快取、`sync` 時把結果帶進去 |
| `wiki.py` `plan_fills` | 新值種類:`s690_count`、`s690_sud_case`、`s690_sud_note`、`s690_spec`、`s690_rep`;看不出值就不填 |
| `data/config/xfer690.json` | 書目四個 target 加欄;新增 `TW影像GCS` 兩個 target(`after` 為「公開影像上傳」「公告說明書上傳」,key = 書目系統的期數) |
| 前端 `xfer690.js` | 不加新畫面;預覽的 tooltip 與紅框沿用現有元件 |

`program/xfer690/` 不同步到 TIPO flow check;不新增任何相依。

## 錯誤處理

- s690 連不上 / HTTP 錯 / 回傳格式不對:那期記 `error`,預覽在相關格顯示「s690 查詢失敗:…」,下次抓信再試。
- 不會因為 s690 失敗影響抓信、狀態判定或其他欄的寫入。
