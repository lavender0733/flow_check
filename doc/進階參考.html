進階參考

操作與功能見說明首頁;本頁放 690 的規則、設定、檔案位置與 HTTP API。開發架構與規範見 .claude/CLAUDE.md。

改完 program/core/、program/common/ 或 program/xfer690/ 下的任何 .py 或 config.json 後需重新啟動才生效(網頁上方會自動跳「需重啟」橫幅提醒);改 web/ 下的網頁檔重整即可。xfer690.json 每次抓信都會重讀。

690 資轉監控規則

s690 的 Rundeck 每跑一個步驟就寄一封通知信(主旨像 🔴【FAILURE】[s690] 012001-techreport-pdf-step1-raw | 01-tw/20-techreport-pdf)。Rundeck 在內網連不到,所以只靠信。

連線與憑證

  • Gmail 走公開的 Google 端點,不用開 VPN、不用換網路。授權分頁被關掉就按「重新開啟授權頁」;已授權時卡片顯示登出(刪掉 token、停止抓信)。
  • 用 690授權.bat 授權完成後會印出近 30 天每個 job 的統計表(封數、成功失敗、時刻),拿來核對系統清單。
  • KM 只開 Innovue OAuth 登入,程式沒辦法自己登入,所以要貼瀏覽器的 jwt。伺服器先跟 KM 確認有效才收下,存進 data/config/xfer690_secrets.json 的 wiki_jwt;KM 續期發的新憑證會自動寫回,失效時清掉、卡片要你重貼。
  • 不開 VPN 也能用 KM:那時 KM 走 Cloudflare,它擋 Python 預設的 User-Agent,程式送自己的 flow-check-xfer690/1。被閘道擋下(HTTP 401/403)算網路問題,不會清掉 wiki_jwt。
  • 三個機密檔(gmail_credentials.json、gmail_token_<機器>.json、xfer690_secrets.json)都不在版控內,也不會同步到 TIPO flow check。KM 登入憑證網頁送出後不會再回傳或顯示。

畫面細節

  • 每日資轉:磚裡有狀態、收信或最晚時間,以及步驟一顆點(步驟和它的 -check 併成一顆,兩個都成功才算綠)。系統有設定 reruns 的(目前是搜尋後續),磚塊底下多一行「補跑」:近 7 天每個補跑作業只看最新一次,成功的一顆綠點,失敗的寫出作業名稱和「失敗」log 連結,算在每日資轉的警示。設了 rerun_date 的(目前是技術報告)補跑前幾天的資料時,也列在「補跑」,並算回資料那一天;KM 上那天原本填的「-」(nodata_value)補跑成功後改成 v,其他人填的值照樣不覆寫。
  • TWA 公開 / TWB 公告:只追蹤最近一個月(TWA 2 期、TWB 3 期);近一個月內補跑的舊期列在「更早的期」。
  • 其他作業:手動作業依作業名稱(去掉 -stepN-…)一個作業一塊磚(新的在前,失敗的整塊淡紅底),同名的不論成功或失敗只列最新一次(失敗會算警示);維運 99xxxx 只列最後一次。
  • 「失敗」連結打開那封信附的 .log,自動捲到 error: 那一行(伺服器當下抓,不存檔)。主頁籤的 ⚠ = 有轉置警示(690資轉)或連線問題(信件與連線)。

狀態的意思

狀態意思
成功步驟與它的 check 都成功
無資料step1-raw 失敗,原因是 GCS 資料夾無檔案。每日系統不算警示,KM 那幾格填 -(wiki.nodata_value),不打 v;期別系統代表那期檔案還沒到,算警示、不寫 KM
失敗有失敗信。之後的步驟顯示「沒有執行」
該到沒到過了 expect_by 還沒收到信;或一次執行收到幾步之後就沒信了(期別系統以最後一封信後 2 小時為期限)
還沒跑到還沒到 expect_by
無法判定主旨的狀態字不是 SUCCESS / FAILURE

同一期跑了好幾次(例如前一天無資料、隔天重跑成功)以最後一次為準。不定期的系統(全文、英譯)沒有排程,不會報「該到沒到」。

期別怎麼對應到 KM 的列

  • 每日系統:一天一列,列鍵是執行日期(2026/10/01)。
  • 書目、雜項、全文:列鍵是公告期數,取自 log 的 RUNDECK:DATA:VOL(手動補跑舊期也會歸到正確的期,不看收信日期)。期數與日期互換:TWB 每月 1、11、21 日,VOL = (年−1973)×100 + (月−1)×3 + 第幾旬;TWA 每月 1、16 日,VOL = (年−2002)×100 + (月−1)×2 + 上/下半月。
  • 英譯(TW英譯En 頁):列鍵是期數區間(5325 ~ 5327),取自 log 的 FILE_I(公告)/ FILE(公開)檔名 TW__I_20260901_5325_to_20260921_5327_complete。同一個區間重跑好幾次是同一列,每個步驟以最後一次為準。無資料(那批檔案還沒到)跟期別系統一樣算警示、不寫 KM。
  • TW影像GCS 頁:列跟書目的期數走(書目有收到信的期),說明書 / 代表圖由 s690 抽查(見下面)。
  • 一次手動執行可能連跑好幾期,所以同一系統的信以「step1-raw 那封」或「跟上一封相隔超過 2 小時」切段,段裡其他信沿用該段的期數。

寫 KM 的規則

  • 只填空格:格子已經有值就不動(2026xxxx 這種佔位字當空格);值不同在預覽裡用波浪底線標出。
  • 打 v 的格:那一步和它的 check 都成功才打。
  • 筆數欄(書目頁的 Biblio、Gazette SUD):填 L1 那封信 log 的 writes,而且整期每一步都成功才填。
  • 缺列就照列鍵順序插入;列鍵比表格最舊的一列還舊時不插入。
  • 目標列以外的每一行逐位元組不變;欄名對不上時整張表不寫;內容沒變不送更新;一頁失敗不影響其他頁。
  • 手動修改:KM 登記頁點任一格可改(Enter 存、Esc 取消),寫入時一起送出。這是唯一會覆寫非空值的路徑,而且伺服器會先確認頁面上那格還是你看到的值,不是就整筆不寫、列為衝突。
  • xfer690.json 的 wiki.dry_run 是 true 時,按「寫入 KM」只算結果、不真的寫。
  • s690 查詢(抓完信後在背景查,整期成功才查;結果存在快取,同一期不重查,重跑過才重查):
    • 690查詢筆數:進階檢索、案件類型 TWA / TWB、PD:[那期日期 TO 那期日期] 的總筆數。跟 Biblio 不同時照填,預覽標波浪線。
    • SUD抽測案例 / 備註:從雜項 log 取這期有的雜項類型(不含公告目錄、發明公開目錄),MS:(類型…) AND MS:<卷> AND MS:<期> 取第一筆「雜項真的刊在這一期」的案件(最多看 120 筆)。讓與比對書目的目前專利權人、消滅比對案件狀態,其他類型只確認查得到。正確 → 案例填 TW + 公開 / 公告號、備註填 成功;不符或找不到 → 兩格都不填,預覽的 tooltip 寫原因。
    • TW影像GCS:OGV:<卷> AND OGN:<期> 的第一筆,有說明書 / 代表圖就打 v;「抽查案號」填那一筆的 TW + 公開 / 公告號(說明書 / 代表圖沒有也照填)。
    • s690 連不上不影響抓信與其他欄;s690_enabled 可以關掉。

流量預算

抓信一律先只抓主旨與時間(每封約 2 KB),只有三種信才下載全文:失敗信、期別系統與英譯每段的第一封(帶出期數)、要填筆數的步驟。單封超過 max_raw_kb(預設 512 KB)也不下載。實測:第一次抓 45 天 495 封共 2.75 MB,之後每輪幾 KB。

HTTP API 端點

常駐伺服器(預設 http://127.0.0.1:8765)的全部端點,定義在 program/core/routes.py 的 build_routes()。對不到的路徑一律回 404。

方法路徑用途
GET/api/status當日流量 / 即時速率 / 各網卡明細 / 健康狀態 / 暴增事件 / 今日程式排行 / lan_excluded_bytes 等(前端 5 秒輪詢)
GET/api/traffic/log?date=YYYY-MM-DD&after=N某天的逐分鐘用量明細(網頁用到的欄位;after = 從第 N 筆起,網頁看今天時只補新增的),外加有明細的日期清單
GET/api/traffic/daily每日用量統計(流量報表),今天那筆即時計算
GET/api/config額度、速率下限、本機偏好(notify_*、surge_*、theme)
POST/api/prefs寫回本機偏好,即時套用到執行中的監控(不必重啟)
POST/api/speedtest主動測速:抓一小段量實際 Mbps、判斷有無被限速(每次約耗 8MB)
GET/api/xfer690690 快照:各系統狀態、最近 20 封信、Gmail 與 KM 的狀態、KM 預覽(前端每 60 秒讀)
POST/api/xfer690/refresh690「立即更新」:前景抓一次信,回傳新快照
GET/api/xfer690/log?id=<信件 id>那封通知信附的 .log 純文字(當下從 Gmail 抓,不存檔)
POST/api/xfer690/wiki/loginbody {"jwt": "…"}:使用者從瀏覽器複製的 KM jwt。確認有效才存進 xfer690_secrets.json,回應不回顯

POST/api/xfer690/gmail/authorize回傳 Google 同意頁網址 {"ok", "url"}(網頁在新分頁開;10 分鐘內有效,再按一次換新的)

POST/api/xfer690/wiki/write寫入 KM(body {"edits": [...]} 是使用者手改的格);沒登入回 409 {"error": "not_logged_in"}
