版本紀錄

7.3.1 — 2026-09-15

  • 畫面與用法完全沒變,這一版只動了「以後要加新頁籤時有多麻煩」。
  • 加一個新頁籤,從「改 5 個地方」變成「丟兩個新檔」:以前要在 index.html 加按鈕、加兩處標記,還要到 main.js 補上頁籤名單與切換動作 —— 漏掉最後那一項最惱人,按鈕會冒出來、點下去卻沒反應,而且畫面上不會有任何錯誤訊息。現在只要放進兩個新檔(一個畫面、一支程式),現有檔案一行都不用改,重整瀏覽器就看得到,連重啟都不用。
  • 備份檔放在程式資料夾裡是安全的:新做法只認「畫面與程式成對」的檔案,所以像 monitor_舊版.js 這種備份、或 Google Drive 同步打架時自己長出來的 monitor (1).js,都不會被載進網頁。這件事以前會出事而且很難查:那種檔案裡的舊程式會悄悄蓋掉新版的,畫面看起來就是「明明改了卻沒變」。

7.3.0 — 2026-09-15

  • 檢索控制台改為單一跑法:填筆數 →「▶ 開始」,跑完該筆數或按「■ 立即停止」就結束。版面跟著調整:筆數欄與開始 / 停止改在同一排。單次筆數上限(預設 2000)仍在。
  • 程式大整理(畫面與用法完全不變):主程式 traffic_monitor.py 原本是一個 1,536 行的大檔,什麼都混在裡面;現在拆成幾個各司其職的小檔(流量取樣、檢索排程、網頁端點、錯誤與重啟偵測),主程式只剩 167 行的「啟動流程」。兩支伺服器(流量監控 8765、年度統計 8766)本來各自抄了一整套一模一樣的網頁伺服器程式,現在共用同一套。對使用者來說沒有任何差別,但以後要加新功能會快很多、也不容易改壞。
  • 修掉一個一直存在的網址比對錯誤:以前打錯的網址(例如多打幾個字的 /api/statusXYZ)會被誤認成正確網址而回傳資料;現在會正確回「找不到」。另外有兩個網址一直必須「排對順序」才不會互相吃掉,現在改成精準比對,順序再也不影響。
  • 「需重啟」的提醒更可靠:以前是照一張寫死的檔案清單去看有沒有被改過,拆檔或加新檔很容易漏掉;現在改成自動掃整個程式資料夾,新檔會自動納入。
  • 加上版本控制(git):程式碼從此有完整的修改歷史、隨時可回到任何一版。三個含驗證碼明碼的檔案(api_keys.json、各機的 api_config_<機器>.json、api_quota_baseline.json)已明確排除,絕不會被記錄進去。你的資料夾 data/ 也不在其中。

7.2.1 — 2026-09-14

  • 修正「達標情況分析的月份選單只剩當月、之前的月份不見了」:8 月的數據是在另一台電腦上按「更新計算」留下的,換到這台電腦看,月份選單就只列得出當月。原因是每台電腦的快照各自存成一個檔(這是為了避免兩台同時按更新、在 Google Drive 上互相覆蓋),但畫圖時只讀了自己這台的檔。其實這頁的數字全部來自你手動下載的後台匯出檔,是全站總量,跟哪台電腦跑過檢索沒有關係。現在改成畫圖時把所有電腦的快照合併起來,之前的月份就都回來了(存檔仍然分開,防覆蓋不受影響,圖上也不會出現機器名稱)。同一個資料日期若兩台都按過更新,只顯示較晚的那一筆,不會長出兩個點。要重跑 stop_monitor.bat → start_monitor.bat 才生效(這次改的是程式本體,不是只重整瀏覽器就好)。

7.2.0 — 2026-08-17

  • 新增「達標情況分析」圖表(檢索進度頁):按一次「更新計算」,就把當下由最新「簡易版 / API」匯出檔算出的累積筆數留成一個點,連成折線看進度走勢。橫軸是匯出檔的資料最後日期,不是你按按鈕的時間;同一份資料重複按只算一個點。快照從這個功能上線後才開始累積,不會回推以前的資料。
  • 兩種看法可切換:「總數」只畫總累積筆數與金色虛線的月目標兩條線,滑鼠移上去顯示當下總數與月達成率;「簡易版＋API」用藍線 / 橘線比較兩種檢索方式的累積筆數,可以用「顯示」勾選鈕單獨隱藏其中一條。
  • 可切換月份:右上角下拉選單列出已經有快照的月份。切月份或切圖表只是看資料,不會多存快照。

7.0.4 — 2026-06-29

  • 修正「流量監控頁面靜悄悄不更新、卻完全沒有提示」:有人回報頁面過了好幾分鐘都沒更新數據、也沒跳任何訊息。原因是頁面每 5 秒會去跟程式要一次最新數據,但若程式被關掉、連線中斷,或電腦剛從睡眠喚醒導致要不到數據時,頁面以前會把錯誤默默吞掉—— 數字和「最後更新」就停在原地,卻一個字都沒提醒,看起來像還在跑其實已經斷了。現在改成:連續要不到數據超過約 30 秒就跳橫幅「⚠️ 已 N 秒無法連線到流量監控」,提醒你確認執行視窗是否還開著、或重新執行 start_monitor.bat;重新連上後橫幅會自動消失。純前端,重整瀏覽器(Ctrl+F5)即生效。

7.0.3 — 2026-06-26

  • 新增「今日進度」小區塊(爬取統計頁上方):把「今日該檢索多少 / 今日已完成多少」一眼呈現,配進度條 —— 還沒做完顯示「今日還需 N 筆」、做到了顯示「🎉 今日已達標」、照目前速度月底就能達標則顯示「✓ 今日無需額外檢索」。沒放匯出檔、算不出月目標時只顯示「今日已完成 N 筆」。
  • 新增「今日達標慶祝」:當天檢索筆數達到「每個工作日需檢索」時跳彩帶 + 祝賀橫幅,一天最多一次。
  • 流量明細改「網卡 / 用量明細」可切換頁籤:把 7.0.2 的「計費明細」整合進可收合、可切頁籤的面板;「用量明細」把計費明細與流量暴增合併成同一張近 5 分鐘時間軸表,暴增的列標 🔺 並列出推估兇手程式。純前端,重整瀏覽器即生效。

7.0.2 — 2026-06-22

  • 修正「走內網下載大檔卻仍被算進 2GB 額度」:有人回報用 FileZilla/SFTP 走內網下載,流量還是被計入,單日一度衝到 ~6GB(303%)。問題出在偵測短命內網連線(像 FTP 每個檔案開一條、很快就關)時會被整條漏掉。已修正:這類連線一出現就立刻計量、把內網探測調得更密、網段設定改得更穩妥(內網確實排除、同時釘死 GPSS 對外流量永遠計入)。
  • 新增頁內「計費明細」記錄(每分鐘一列:NIC 收 / 內網收 / 外網收 / 實扣收 / 計入收 / 計入送),方便現場核對。實測一筆 3.14GB 內網下載,計入額度的部分趨近於 0,確認修好。

7.0.0 — 2026-06-18

  • 程式內部大整理(功能不變):把原本擠在單一大檔的程式拆成幾個各司其職的小檔(流量量測、設定/統計資料、API 額度計算等),較好維護;對使用方式沒有任何影響。
  • 修正「額度已滿提醒關掉後又一直跳回來」:檢索撞到 TIPO 額度上限時會跳提醒,以前按「關閉」只是暫時藏起來、重整網頁又冒出來。現在按關閉就真的消失,之後再撞額度才會再提醒。
  • 減少「程式碼有更新、請重啟」誤報:雲端硬碟同步有時只動了檔案時間、內容沒變也會誤判要重啟。改成比對內容,只有真的改了程式才提醒。
  • 修正啟動批次檔(.bat)在某些情況下閃退(換行格式問題)。

5.4.0 — 2026-06-17

  • 新增「流量暴增預警」——「是什麼東西突然把流量吃掉」一眼看見:在流量監控頁開啟後,某一分鐘的網路用量若突然暴增(同時超過你設的門檻、且達近期平常用量的好幾倍),就會跳橫幅提醒(桌面通知若已授權也會發),並列出當下最可能在吃流量的程式(例如某個瀏覽器分頁、雲端同步、更新程式)。
    • 怎麼抓兇手:Windows 沒有「每支程式用了多少網路」的現成數字,工具改看「目前正在連網的程式當下讀寫量增加最多的是哪幾個」來推估 —— 只看正在連網的程式,排除純粹在動硬碟的;這是最佳推估、不是精準數字,清單會把「沒在連網」的候選標出來(可能只是剛好在動硬碟)。
    • 不會洗版:同一波長時間下載只提醒一次;一打開頁面看到的「之前就發生過」的暴增只會列在清單、不會硬跳橫幅(可手動按掉)。
    • 可調:開關與「單分鐘達幾 MB 才算暴增」(預設 50MB)就在流量監控頁,設定各台電腦自己記、重開留得住,改完即時生效、不必重啟。

5.3.1 — 2026-06-17

  • 修正「檢索明明跑完、summary 也出來了,任務卻不會自動停,還要手動按停」:檢索程式跑完後,會把這輪零散的結果檔(CSV)併進「當月一個 Excel」。那個 Excel 放在 Google Drive 同步夾、又會越長越大,整份讀進來再整份存回去很慢、有時還會被雲端同步鎖住 —— 而這段併檔是接在 summary 後面、在檢索程式裡做的,所以 summary 都印出來了,程式還卡在併檔沒結束,網頁的任務狀態就一直停在「執行中」、不會自動停;等不到只能手動按停,還可能正好砍在存檔中途、害這輪結果沒併進去。現在併檔改由常駐的監控程式在「任務結束後丟到背景慢慢做」:檢索程式印完 summary 就立刻收工 → 任務即時轉「完成」並自動停,併檔在背景進行、從不卡住你。併檔存檔也改成先寫暫存檔、寫好才一次換上,萬一中途被中斷也不會留下半截的壞檔。筆數/流量統計不受影響(本來就直接讀得到尚未併入的結果檔)。

5.3.0 — 2026-06-17

  • 剛重開機、第一次打開工具時「爬取統計」載入很慢 → 開好就先在背景幫你算好:電腦剛開機時,程式記在記憶體裡的暫存都還是空的、當月資料又要重算,加上檔案放在 Google Drive 同步夾、剛開機常常還是「用到才下載」,第一次讀每個月份的檔都得即時抓下來 —— 這些等待以前全擠在你按下「爬取統計」那一刻的轉圈圈上。現在工具一啟動,就會在背景先把爬取統計算一遍、把檔案先抓下來熱好。一開始看到的是流量監控頁,通常過幾秒才會點到爬取統計,這段時間剛好讓背景把重活做完,點開時就是現成的。純粹加速:背景沒算成不影響任何數字,真的一開就馬上點,也只是跟以前一樣等一下、不會更慢。

5.2.0 — 2026-06-16

  • 「爬取統計」與「檢索進度」載入變快:這兩頁原本每次都把同一份檔案從頭重算一遍,檔案越大越慢。改成記住上次算好的結果,檔案沒變就直接用、不重算(下載了新的匯出檔、或又跑了新檢索讓資料變動,才會重算),所以數字一樣準。
    • 檢索進度快很多:它要讀的簡易版匯出檔常有 2MB 左右,以前開這頁、按「更新計算」都要重讀整份;現在沒換新檔就秒開,換了新檔按「更新計算」才重讀(不會給你舊數字)。
    • 爬取統計也較快:同一份當月檔以前會被重複拆好幾次,現在一次請求只拆一次、共用;檢索進行中也不再每寫一批就重抓一次統計,改成最多每 12 秒更新一次(切到這頁、或檢索一結束會立刻更新到最新)。

5.1.2 — 2026-06-16

  • 改用量通知的提醒 % 時,旁邊會跳出確認文字:例如「✓ 已更新:用量達 80% 時提醒」,幾秒後自動消失。讓你一眼確認設定有改到、改成幾 %。

5.1.1 — 2026-06-16

  • 修正「重整網頁卻還是跑到舊版」:網頁程式檔原本會被瀏覽器快取住,改了東西重整有時不生效、甚至新舊混用(例如用量通知開關記得了、門檻數字卻沒套用)。已讓程式端要求瀏覽器不要快取、每次都拿最新版。升級後請先強制重新整理一次(Ctrl+F5)或完全關掉瀏覽器再開,把舊的清掉一次,之後就會自動更新。

5.1.0 — 2026-06-16

  • 「用量通知」開關現在重開一定維持上次設定:原本只記在瀏覽器裡,若瀏覽器設成「關閉時清除網站資料」或換了瀏覽器就會掉。改成記在程式端(各台電腦自己記自己的),重新打開就還原上次的開關與門檻;舊設定會自動帶過去,不必重設。

5.0.1 — 2026-06-15

  • 修正啟動時偶發「無法連上 127.0.0.1」、要重整才載得出來:原本啟動批次檔在伺服器還沒準備好之前就先開瀏覽器,瀏覽器搶先連線就會撲空。改成由程式在伺服器就緒後才自動開瀏覽器,第一下就連得上。重新連上網路、Google Drive 正忙著同步時尤其明顯,此版一併解決。

5.0.0 — 2026-06-15 (原 v1.9)

  • 網頁前端模組化重構:原本單一網頁檔(含一大包程式與內嵌樣式)拆成「外殼 + 各分頁(partials/)+ 各功能 JS(js/)+ 外部 CSS(style.css)」。仍是免打包的純 HTML/JS(相容 Google Drive 同步),改某個分頁重整瀏覽器即生效、不必重啟。純整理,使用上沒有差別。
  • 檢索結果改「每月一個 Excel」:從各機一個大檔改成每台每月一個(summary_<機器>_<YYYY-MM>.xlsx,仍一天一張工作表),歷史月份不再被反覆改寫、同步更輕;首次會自動把舊單檔依日期拆成各月檔。統計快取也移出同步資料夾、改放本機,避免一直洗版雲端。
  • 伺服器健康提醒搬到頁面:後端出錯,或程式碼改過(需重啟才生效)時,頁面會直接跳橫幅提醒,不必再去翻黑色執行視窗。

4.0.0 — 2026-06-12 (原 v1.8)

  • API 驗證碼改「驗證碼池」:原本一台電腦填一組 userCode,改成集中一份驗證碼池(api_keys.json),各機只記目前選用哪一組;要切換在控制台下拉直接換、不必改設定檔。驗證碼一律只顯示前 4 碼。
  • 傳統檢索(前端)流量大幅優化:500 筆從約 900 MB 壓到約 11.5 MB(省約 98%),與 API 版同量級。主要靠把每筆查詢都重抓的前端 JS 在程式內快取(第一次下載後存記憶體、之後從記憶體餵回),並改用更精準的流量計量方式。

3.3.0 — 2026-06-11 (原 v1.7)

  • 流量監控新增「限速偵測(網速)」:超過每日額度後局網是用降速來執行上限,故改用網速判斷有沒有被限速、加給生效了沒。被動看近幾分鐘的最高下載速率(不耗流量),或按「測速」實際量一小段(較可靠,每次約耗 8MB)。
  • 流量監控新增「用量通知」:可設定用量達某比例(預設 80%)就提醒;用頁內視窗 + 紅色橫幅 + 分頁圖示紅點三管齊下,不依賴桌面通知權限(桌機封鎖桌面通知也照樣會提醒)。
  • 傳統檢索抗管制調校:降低瞬時負載、被管制時改「先冷卻再續跑」而非立刻中止,提高長跑的成功率。

3.2.0 — 2026-06-10 (原 v1.6)

  • 檢索改兩段式(公開號 + 申請號):每批先用公開/公告號(PN)查,沒命中的再用申請號(AN)補查一次,清單裡的申請號不再靜默查無;查無不耗額度,只多花真正找到的那些。
  • 撞額度立即停止:收到 Over download quantity 就停本輪、不暫停重試(stop_on_quota,預設開),待額度恢復自行重跑;撞牆 / 恢復都會記事件到 run_log(含機器、時間)供排查重置週期。
