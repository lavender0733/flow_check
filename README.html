Flow Check — 流量監控 + 690 資轉監控 v8.1.0

一個放在自己電腦上的小工具,量測每天用掉多少網路流量(對著每日 2GB 的額度),並提供流量報表,拿來跟公司反映連線問題。平時在背景執行,要看時打開瀏覽器就好。

690 資轉監控讀 s690 Rundeck 的通知信,顯示每個轉置系統每天、每一期是成功、失敗、無資料還是沒來,並在 KM 的「資料轉置登記」表格裡登記。

使用的技術

  • Python 3.13
  • psutil 7.2.2 —— 讀網卡累積流量
  • Windows ESTATS —— 逐條 TCP 連線的收發量(內網排除、程式歸因用)
  • google-auth-oauthlib —— 690:以唯讀權限讀 Gmail
  • Wiki.js GraphQL —— 690:寫入資料轉置登記表
  • HTML / CSS / JavaScript(免打包、無框架)

安裝說明

  1. 電腦要有 Python(安裝時勾「Add Python to PATH」)。
  2. 把整個 flow_check 資料夾放到那台電腦(或放在 Google Drive 同步夾裡)。
  3. 第一次啟動時會自動安裝 psutil,不用另外裝。

多台電腦共用同一個 Google Drive 資料夾也可以:每台的流量資料以主機名稱分檔,各自獨立計算,不會互相覆蓋。

啟動 / 關閉

動作做法
啟動雙擊 start_monitor.bat,會自動打開瀏覽器到 http://127.0.0.1:8765
關閉雙擊 stop_monitor.bat(只關這個工具,不影響其他程式)
內網排除診斷雙擊 diag_lan.bat(需管理員)。每 10 秒逐連線列出對方 IP、內外網分類與收發量,並和執行中主工具的實扣量對照。平常不必開,內網排除算得怪怪的時候再用。
690 Gmail 授權雙擊 690授權.bat(每台電腦一次,或授權失效時)。瀏覽器跳出 Google 登入,同意唯讀權限即可。

為什麼會跳 UAC(管理員):內網排除與程式歸因要讀 Windows ESTATS(每條 TCP 連線的收發量),這需要管理員身分。第一次啟動會跳一次 UAC 並建立排程工作,之後啟動不再詢問。按「取消」也能跑,只是內網排除與程式歸因停用,總流量照常計算。

主要功能

流量監控

  • 今日用量:今天用掉 / 還剩多少流量,以及即時下載、上傳速率。
  • 排除內網流量(一律開啟):走內網(NAS、區網 FTP 等)的傳輸不算進對外額度,依對方 IP 逐條連線判斷。
  • 用量通知:達設定比例以頁內視窗 + 紅幅 + 分頁紅點提醒。
  • 流量暴增預警:某一分鐘突然用很多時跳提醒,並列出當下耗流量最多的程式。
  • 限速偵測(網速):被動看近期最高下載速率,或按「測速」實量(每次約 8MB)。
  • 今日程式排行:今天每支程式累計吃掉多少額度(含「未歸因」的 UDP/QUIC 與「監控未執行期間」)。額度莫名用完時先看這裡。
  • 用量明細:每分鐘一筆,由伺服器記錄 —— 網頁沒開也照記,保留 31 天、可切換日期回頭查。
  • 暴增紀錄:當天的暴增事件,依程式與時間收合,展開看 IP、PID 與流量。

流量報表

  • 每日流量:每天一根堆疊柱,分出 ssh、Claude Code、VS Code 與其他;可切「合計 / 上傳 / 下載」、期間「最近 14 天 / 31 天 / 全部」。
  • 逐時:點某一天,換成那天 8–20 點的逐時折線圖,看幾支程式是不是同時段一起升降。按「← 每日」回來。
  • 看每日數字:展開表格看每天的數字,方便截圖或抄給公司。
  • 每日統計長期保存(不像用量明細只留 31 天),一天只寫一次。要分開統計的程式可在 config.json 的 report_apps 調整。

外觀

  • 頁籤列最右邊的「外觀」選單可切換深色(預設)/ 淺色 / 原版;數字與功能完全不變,只換視覺。
  • 選擇記在這台電腦上(不是瀏覽器),換瀏覽器、重開機都還在;多台電腦各自獨立。

690 資轉監控

網頁打開時自動讀一次 [s690] 通知信,之後要看新的狀態請按「立即更新」(不在背景定時抓)。兩個頁籤:

  • 690資轉:
    • 每日資轉:今天每個每日系統一列,每個步驟一顆點。搜尋後續的補跑列在那一列底下(成功一顆點,失敗附 log)。
    • TWA 公開 / TWB 公告:全文、書目、雜項、英譯 × 公告期數,只追蹤最近一個月;補跑的舊期列在「更早的期」。點一格看那期的細節。
    • 其他作業:不在系統清單上的手動作業(同名的只列最新一次),以及維運 99xxxx。
    • KM 登記:登入 KM 後顯示填好的表格預覽,按「寫入 KM」才寫。點任一格可以手動修改。
  • 信件與連線:Gmail 授權、KM 登入(在這裡按「登入 KM」)、最近收到的信。
  • 失敗項目的「失敗」兩個字就是連結,點了直接看那封信附的 log。分類上的紅色數字是要處理的件數,頁籤上的 ⚠ 表示有狀況。
  • 寫 KM 時只填空格,不覆寫人填的值(你在畫面上明確改過的格除外)。

第一次設定(每台電腦一次):

  1. 確認 data/config/gmail_credentials.json 在(GCP 的 OAuth 用戶端)。
  2. 雙擊 690授權.bat,用 alicia.huang@innovue.ltd 同意唯讀權限。
  3. 要寫 KM 的話,data/config/xfer690.json 的 wiki.enabled 要是 true。在瀏覽器用 Innovue OAuth 登入 KM,按 F12 → Application → Cookies 複製 jwt 的值,貼到「信件與連線」的 KM 卡片按「登入 KM」(存在 data/config/xfer690_secrets.json,重開不用重貼)。
  4. 重開 start_monitor.bat(第一次會自動安裝 690 需要的套件;裝不起來只停用 690,流量監控照常)。

規則與設定的細節見進階參考與 doc/README.md 的「690 資轉監控」一節。
